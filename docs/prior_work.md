# 선행 연구와 이 저장소의 관계

이 프로젝트의 QAT(`tools/qat.py`)는 **컬럼별 가중치 양자화 + partial-sum 양자화**라는
착상을 선행 연구에서 가져왔습니다. 그 출처와, **어디까지 같고 어디부터 다른지**를
여기에 명시합니다. 코드 어느 곳에도 이 기법을 독자적으로 고안한 것처럼 적지 않습니다.

## 출처

> Jiyoon Kim, Kang Eun Jeon, Yulhwa Kim\*, Jong Hwan Ko\*,
> **"Column-wise Quantization of Weights and Partial Sums for Accurate and
> Efficient Compute-In-Memory Accelerators"**, DATE 2025.
> [arXiv:2502.07842](https://arxiv.org/abs/2502.07842) ·
> 저자 공개 구현: <https://github.com/jiyoonkm/ColumnQuant>
> ( \*교신저자. 성균관대학교 — 각각 EIC Lab, IRIS Lab.)

## 그 논문이 해결한 문제

CIM에서는 **ADC가 면적과 에너지를 지배**합니다. 해상도를 낮추면 비용은 줄지만
partial-sum 양자화 오차가 정확도를 떨어뜨립니다.

선행 연구들은 **partial-sum 쪽 단위만** 잘게 쪼개 왔습니다(layer → array → column).
이 논문의 관찰은 **가중치 단위가 천장을 정한다**는 것입니다 — 가중치를 layer 단위로
뭉뚱그리면 partial-sum을 아무리 잘게 나눠도 그 위로 못 올라갑니다.

그래서 **둘의 단위를 컬럼별로 정렬**했고, 세 가지를 얻었습니다.

| | |
|---|---|
| **정확도** | dequantization 곱셈 횟수를 **늘리지 않고** 개선 (`sw·sp`를 미리 곱해 둠) |
| **학습** | 단위가 맞으니 **1단계 QAT**로 충분 — 2단계 대비 학습 비용 34.27% 감소 |
| **편차 내성** | 컬럼마다 독립 스케일이라 셀 편차에 강함 |

보고된 정확도 (ResNet-20/CIFAR-10·CIFAR-100, ResNet-18/ImageNet):
기존 최고 대비 각각 **+0.99 / +2.69 / +1.01 %p**.

## 이 저장소가 가져온 것

`tools/qat.py`:

- **컬럼별 가중치 가짜 양자화** — `_CrossbarQuantPrune`, 출력 채널(dim 0)마다 스케일 하나
- **컬럼별 partial-sum 양자화** — `_PartialSumQuant`, 레이어 출력(dim 1)을 `adc_bits`로
- **한 단계 학습** — 둘을 함께 걸고 그대로 미세조정

착상과 배치는 위 논문의 것입니다.

## 이 저장소가 **하지 않은** 것 — 중요

같은 이름을 쓰지만 **논문의 핵심 장치 두 개가 빠져 있습니다.**

| 논문 | 이 저장소 |
|---|---|
| **LSQ 기반 학습 가능한 스케일**을 가중치·partial-sum 양쪽에 (논문의 실제 기여) | **학습하지 않습니다.** 매 forward마다 `per_channel_max / qmax`로 다시 계산하는 고정 스케일 |
| 가중치를 **실제 배열 크기로 타일링**하고 배열별 partial-sum을 양자화 | 타일링 없음. **레이어 출력 전체**를 partial sum의 대용으로 씁니다 |
| 비트 분할(다중 셀), 전용 합성곱 프레임워크(타일링 + 그룹 합성곱) | 없음 |

즉 **"C71을 구현했다"고 말하면 사실과 다릅니다.**
정확한 표현은 **"C71의 컬럼별 정렬이라는 착상을, 학습 가능한 스케일 없이 단순화해
적용했다"** 입니다. 논문이 측정한 정확도 이득이 이 저장소에서 그대로 재현된다고
주장할 근거도 없습니다.

## 이 저장소가 **더한** 것

논문이 다루지 않는 층에 있습니다.

| | C71 | 이 저장소 |
|---|---|---|
| 묻는 질문 | *어떻게* 양자화할 것인가 | *얼마나* 양자화할 것인가 |
| 비트 수 | 실험 설정으로 **고정**(3b·4b) | **층마다 탐색**(`tools/search.py`) |
| 프루닝 | 다루지 않음 | 구조적 컬럼 프루닝, 타일 경계로 스냅 |
| 하드웨어 | 배열 크기 | `HWConfig` 12개 항목 + IR-drop·잡음 검증 |
| 에너지 | 다루지 않음 | 크로스바 패스 기반 추정 + 문헌 보정 |

**두 연구는 겹치는 것이 아니라 위아래로 쌓입니다.** C71은 주어진 비트 수에서
정확도를 끌어내는 방법이고, 이 저장소는 층마다 몇 비트를 줄지를 정합니다.
